# V1.4.5 Enrollment Eligibility Fix

The previous central enrollment form listed all active students before the Course Offering was chosen, which allowed an invalid Student/Offering pair to be selected and only then rejected by the server with `Student is not assigned to the offering group.`

V1.4.5 keeps the strict server-side academic integrity rule and improves the UI: select the Course Offering first, then only matching active students remain selectable. Group matching has priority; if an offering has no Group, Batch matching is used; if neither is set, enrollment is open to any active student.

No D1 migration is required from schema v4.
