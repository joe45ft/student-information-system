# V1.4.5 Friendly Errors Report

## Goal
Make every important user-facing error clearer, actionable, and consistent without exposing sensitive implementation details.

## Improvements
- Reworked validation messages for Students, Users, Academic records, Terms, Course Offerings, Enrollment, Settings and Passwords.
- Reworked enrollment eligibility errors to name the mismatch and tell the operator exactly what to change.
- Improved authentication, CSRF/session expiry, permission-denied, missing-record, CSV import, duplicate-data and dependency-block errors.
- Improved permanent-delete and deactivate blockers with related-record counts and next-step guidance.
- Improved unexpected-error messages while keeping support Request/Reference IDs for Cloudflare Logs.
- Added a consistent notice layout with icon, heading, accessible alert/status behavior, and readable guidance.
- No database schema change and no new runtime dependencies.

## Examples
Old: `Student is not assigned to the offering group.`

New: `Student is assigned to <current group>, but this course offering is for <required group>. Update the student’s Group to match this offering, or select an offering for the student’s current Group.`

Old: `Invalid status.`

New: `Choose a valid status from the available options.`

Old: `Delete blocked by related data: 4 students.`

New: `Delete blocked by related data. Related data: 4 students. Update, close, move, or remove the related records first, then try again.`

## Compatibility
- Schema remains v4.
- All existing routes, permissions, migrations and Cloudflare D1 data remain compatible.
- No migration is required when upgrading from V1.4.4.
