STUDENT IMS NEXT V1.4.0 - ACADEMIC NETWORK DEPLOYMENT

PRE-DEPLOY
1. Use Node.js 20+.
2. Run: npm install
3. Run: npm run build
   Expected result: VALIDATION PASS and all tests pass.

CLOUDFLARE / D1
4. Authenticate Wrangler to the correct Cloudflare account.
5. Confirm the existing production D1 database is bound using binding name DB.
   Fresh installation only, if no database exists yet:
   npx wrangler d1 create student-ims-next-prod --binding DB --update-config
6. Configure AUTH_PEPPER BEFORE creating the first Owner on a fresh installation:
   npx wrangler secret put AUTH_PEPPER
7. IMPORTANT FOR V1.4.0: apply the additive Academic Network migration:
   npm run db:migrate:remote
   This applies migrations/0002_academic_network.sql and adds Terms, Course Offerings and Enrollments.

DEPLOY
8. Run: npm run deploy
9. Check /health (must return ok: true).
10. Check /version (must show 1.4.0).
11. Existing installation: sign in and verify Terms / Semesters, Course Offerings and Enrollments.
12. Fresh installation only: open /setup -> Create Owner -> Login -> Dashboard.

SAFE UPGRADE RULES
- DO NOT reset, delete or recreate the existing production D1 database during an upgrade.
- Migration 0002 is additive and preserves existing Students, Batches, Groups, Lecturers, Subjects, Users and Audit data.
- Back up/export operational data according to your Cloudflare D1 process before any production schema change.
- Keep the existing DB binding named DB.
- Do not commit the AUTH_PEPPER value.
- Do not change AUTH_PEPPER after accounts exist without a planned password migration/reset.
- Do not add Turso/Hono/libSQL or legacy project secrets.
