# V1.4.2 Actions & Safe Delete Report

## Goal
Complete the missing management actions across the system while preserving academic history and existing data relationships.

## Implemented lifecycle model
- ACTIVE → Deactivate/Close → INACTIVE
- INACTIVE → Activate/Reopen
- INACTIVE + zero dependencies → Delete Permanently

## Academic records
Batches, Groups, Lecturers and Subjects now expose lifecycle controls directly in their list Action column. Deactivation is blocked when active dependent data would become inconsistent. Permanent delete is blocked whenever any dependent records still exist.

Terms can be closed only after active Course Offerings are closed. A Term can be deleted only when it is inactive and has no Course Offerings.

Course Offerings can be closed only after active enrollments are completed or dropped. They can be deleted only when inactive and no enrollment history exists. A Duplicate action opens a new pre-filled inactive Offering while deliberately clearing the unique Offering Code.

## Students and bulk operations
Students now have explicit Activate / Deactivate actions. Deactivation is blocked while ACTIVE enrollments exist, and permanent deletion is blocked whenever any enrollment history exists.

Students plus Batches, Groups, Lecturers and Subjects support bulk Activate / Deactivate. A bulk request is capped at 100 selected IDs, uses the same server-side permission/CSRF/dependency rules as individual actions, and reports how many records were changed versus skipped for safety.

## Enrollment
Enrollment remains history-first. ACTIVE or COMPLETED records cannot be permanently removed. A mistaken enrollment must first be marked DROPPED, after which a confirmed Remove action is available.

## Users & security
User Details now includes an explicit Enable/Disable action. Disabling revokes active sessions and still respects Last Owner protection. Pending reset requests can be dismissed without changing the user's password and the action is audited.

## Database
No schema changes. Schema version remains 4.

## Security / audit
All lifecycle changes and permanent deletions are permission checked, CSRF protected, confirmation guarded in the UI, and written to Activity Log.

- Student permanent deletion now preserves academic history: any enrollment history blocks permanent deletion; deactivate the student instead.
